# Static Site, SEO & AI Context 🌐🤖

Every `docmedown build` produces **two kinds of output from one Markdown source**: the live SPA runtime you already know, *and* a fully prerendered static site with SEO metadata and AI-consumable context files. No extra configuration required.

---

## Prerendered static pages

Each document is compiled to `<slug>/index.html` (a document at `guides/intro.md` becomes `/guides/intro/`, and `README.md` becomes the site root):

- The **complete article HTML** is inlined into the page, generated by the same markdown pipeline the runtime uses — callouts, syntax highlighting, and KaTeX included. Crawlers and no-JS visitors see full content.
- The page head carries **title, meta description, canonical URL, Open Graph, Twitter card, and JSON-LD structured data** (`WebSite` + `TechArticle`).
- The runtime script hydrates the page when JavaScript loads; navigation happens through clean path URLs (`pushState`) instead of hash routes on prerendered builds.
- Frontmatter controls: `description`, `noindex` (excludes from search engines and the sitemap), `ogImage`, and the existing `hidden`.

Set `url` in `docs.json` to your canonical origin to also generate **`sitemap.xml`**, **`robots.txt`**, and absolute canonical/OG URLs:

```json
{ "name": "My Docs", "url": "https://docs.example.com" }
```

Skip all of this with `docmedown build --no-static`. Custom `index.html` shells are never overwritten — only the standard DocMeDown shell is replaced by the prerendered home page.

---

## AI context files

Four files land at the documentation root on every build:

| File | Purpose |
| :--- | :--- |
| `llms.txt` | llmstxt.org-format index: every page with a one-line summary |
| `llms-full.txt` | The entire corpus as plain markdown for context stuffing |
| `SKILL.md` | Agent Skill file so coding assistants can discover and use the docs |
| `okf.json` | Versioned machine-readable bundle (slug, headings, plain text, dates) |

---

## MCP server

Expose the built documentation to AI assistants over the Model Context Protocol:

```bash
npx docmedown build ./docs
npx docmedown mcp ./docs
```

Runs as a stdio MCP server reading `_manifest.json` and `_docs.js` — no source tree needed. Tools: `list_docs`, `read_doc` (full markdown + headings + last-modified), `search_docs`, and `resolve_url`. See the [CLI reference](#/guides/cli-reference) for a client configuration example.

---

## What still works exactly as before

Hash routing in script-drop-in mode, dynamic GitHub/GitLab remote documentation, the offline single-file bundle, and component embedding all behave unchanged — static routing only activates on prerendered pages.
